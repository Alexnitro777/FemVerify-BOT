# Privileged Gateway Intents в FemVerify-BOT

Справочник по используемым Gateway Intents (намерениям шлюза) в FemVerify-BOT: зачем они нужны, какие из них являются привилегированными, какие модули бота от них зависят и как их настроить.

---

## 1. Что такое Gateway Intents и Privileged Intents

**Gateway Intents** — это механизм платформы Discord, с помощью которого бот сообщает шлюзу Discord WebSocket, на какие именно категории событий он подписывается. Это оптимизирует трафик и снижает нагрузку на инфраструктуру Discord.

Часть интентов считается обычными (доступны любому боту по умолчанию), а три интента отнесены к категории **привилегированных (Privileged Gateway Intents)**, поскольку они открывают доступ к персональным данным пользователей:
1. **Server Members Intent** (`GuildMembers`) — информация об участниках сервера, их входе, выходе и обновлениях профилей.
2. **Message Content Intent** (`MessageContent`) — доступ к тексту сообщений обычных пользователей в чатах.
3. **Presence Intent** (`GuildPresences`) — статусы пользователей (онлайн, в сети, активность, игры, Spotify).

Для работы с привилегированными интентами их необходимо явно включить в панели управления разработчика (**Discord Developer Portal**). Если бот добавлен более чем на 100 серверов, для их использования требуется пройти верификацию приложения у сотрудников Discord.

---

## 2. Какие интенты настроены в FemVerify-BOT

В коде бота (`src/index.ts`) клиент инициализируется следующим набором интентов:

```ts
intents: [
  GatewayIntentBits.Guilds,
  GatewayIntentBits.GuildMembers,      // ПРИВИЛЕГИРОВАННЫЙ
  GatewayIntentBits.GuildInvites,
  GatewayIntentBits.GuildVoiceStates,
  GatewayIntentBits.GuildMessages,
  GatewayIntentBits.MessageContent,    // ПРИВИЛЕГИРОВАННЫЙ
]
```

Из них **привилегированными являются два: `GatewayIntentBits.GuildMembers` (Server Members Intent) и `GatewayIntentBits.MessageContent` (Message Content Intent)**.

## 3. Зачем боту нужен `GuildMembers` (Server Members Intent)

Без включения `GuildMembers` бот либо выбросит ошибку при запуске (`[DisallowedIntents] Used disallowed intents, check your bot's privileged gateway intents settings`), либо платформа Discord перестанет присылать критически важные события участников.

В FemVerify-BOT на `GuildMembers` завязаны четыре ключевых подсистемы:

### 3.1. Вход новых участников (`Events.GuildMemberAdd` / `src/memberJoin.ts`)
Когда пользователь заходит на сервер, Discord отправляет событие `guildMemberAdd` **только при наличии `GuildMembers` intent**. 

Что бот выполняет в этот момент:
- **Проверка чёрного списка проекта (ЧСП):** проверяет глобальный статус пользователя в БД (`getUserGlobalStatus`). Если участник в ЧС на любом сервере проекта, ему мгновенно выдаётся роль ЧС (`roles.blacklist`), доступ к каналам блокируется, а информация логируется в `blacklistLog`.
- **Автоматическое восстановление верификации:** если пользователь ранее прошёл верификацию на другом сервере сети, бот сразу присваивает ему роль верифицированного участника (`roles.verified`).
- **Выдача роли за тег сервера:** проверяет, указан ли у участника тег сервера в Discord (`user.primaryGuild`), и если да — сразу выдаёт роль за тег (`roles.roleTag`).
- **Определение способа вступления:** совместно с модулем `inviteTracker.ts` сопоставляет счётчики приглашений и определяет, по какому именно инвайту или коду пользователь пришёл на сервер.
- **Приветственное ЛС (`src/welcomeDM.ts`):** отправляет приветствие в личные сообщения пользователям, которые зашли на серверы проекта впервые.

### 3.2. Выход участников с сервера (`Events.GuildMemberRemove` / `src/leaveCleanup.ts`)
Событие `guildMemberRemove` также доставляется **исключительно при активном `GuildMembers` intent**.

Что происходит при выходе участника:
- Если у участника была активная (необработанная) анкета на верификацию или апелляция, её статус в базе данных автоматически переводится в `left` («вышел с сервера»).
- Сообщение с карточкой модерации в канале рассмотрения (`reviewMessageUrl`) деактивируется: кнопки отключаются, модераторы видят отметку о выходе заявителя.
- Приватный текстовый канал вопросов (`questionChannelId`), созданный модераторами для этой анкеты или апелляции, удаляется, предотвращая накопление брошенных каналов в категории.

### 3.3. Отслеживание тега сервера и статусов (`GUILD_MEMBER_UPDATE` / `src/roleTag.ts` и `src/voiceKick.ts`)
- **Роль за тег сервера (`src/roleTag.ts`):** бот слушает обновления профилей участников через пакет `GUILD_MEMBER_UPDATE`. Когда участник устанавливает тег сервера в своём профиле Discord, бот автоматически выдаёт ему роль `roles.roleTag` и пишет об этом в канал лога тегов (`channels.tagLog`). Когда тег убирается — роль снимается. Без интента эти события не приходят.
- **Кик из голосовых каналов при ЧС (`src/voiceKick.ts`):** бот слушает `Events.GuildMemberUpdate`. Если участник находится в голосовом канале и в этот момент получает роль ЧСП, бот немедленно принудительно отключает его от голосового канала (`kickBlacklistedFromVoice`).

### 3.4. Получение списка участников и синхронизация (`guild.members.fetch()`)
Без интента `GuildMembers` вызов метода `guild.members.fetch()` для загрузки всех участников сервера блокируется Discord API.

Где это применяется:
- **Синхронизация роли за тег при старте бота (`syncAllTagRoles` в `src/roleTag.ts`):** при запуске бот опрашивает всех участников серверов, сверяет наличие тега и восстанавливает/снимает роль у тех участников, которые изменили профиль во время перезапуска бота.
- **Команда `/тег` (`src/commands/tag.ts`):** запрашивает полный состав участников сервера через `guild.members.fetch()` для расчёта статистики: общее число участников, процент носителей тега, активные пользователи.
- **Команда `/синхронизировать` (`src/commands/sync_all.ts`):** перебирает участников и применяет статус ЧСП / верификации по всем серверам проекта.
- **Работа кнопок и модальных окон модерации:** при одобрении анкеты, снятии/выдаче ЧСП (`src/buttons/review.ts`, `src/buttons/appealReview.ts`, `src/modals/*`) бот извлекает объект участника (`GuildMember`) через `guild.members.fetch(userId)`, чтобы производить манипуляции с ролями (`member.roles.add`, `member.roles.remove`, `blacklistMemberRoles`, `restoreMemberRoles`), даже если участника нет в текущем кратковременном кэше памяти.

## 4. Другие привилегированные интенты

| Привилегированный интент | Используется? | Причина |
|---|:---:|---|
| **Server Members Intent** (`GuildMembers`) | **ДА** | Необходим для регистрации входа/выхода, синхронизации ролей, тега сервера и управления участниками. |
| **Message Content Intent** (`MessageContent`) | **ДА** | Необходим для чтения текста сообщений участников в каналах-вопросах при их закрытии и архивации в логи (`channels.questionLog`/`channels.decisions`), а также для работы канала-ловушки (`src/trapChannel.ts`) для моментального реагирования на спам и вредоносные сообщения. |
| **Presence Intent** (`GuildPresences`) | **НЕТ** | Бот не отслеживает активность участников (игры, музыку Spotify, сетевой статус онлайн/невидимка). Тег сервера проверяется напрямую из атрибутов профиля участника (`user.primaryGuild`), что относится к `GuildMembers`, а не к `Presences`. |

## 5. Обычные (непривилегированные) интенты бота

В дополнение к привилегированным интентам, бот запрашивает четыре стандартных интента, не требующих специального одобрения Discord:

1. **`GatewayIntentBits.Guilds`** — базовый интент для получения информации о серверах, текстовых каналах, категориях и ролях.
2. **`GatewayIntentBits.GuildInvites`** — отслеживание метаданных приглашений (инвайтов). Используется модулем `src/inviteTracker.ts` для определения, по какой именно ссылке-приглашению пришёл новый участник. Для корректной работы этого интента боту также требуется право Discord «Управление сервером» (`Manage Guild`).
3. **`GatewayIntentBits.GuildVoiceStates`** — отслеживание состояния голосовых каналов. Используется модулем `src/voiceKick.ts` для моментального отключения нарушителей из ЧСП при попытке зайти в войс.
4. **`GatewayIntentBits.GuildMessages`** — базовый интент для работы с сообщениями в гильдиях. Используется для получения событий отправки сообщений (`Events.MessageCreate`) в модуле канала-ловушки `src/trapChannel.ts`.

## 6. Как включить Privileged Intents в Discord Developer Portal

1. Перейдите на портал разработчиков: [Discord Developer Portal — Applications](https://discord.com/developers/applications).
2. Выберите ваше приложение (бота).
3. В левом меню перейдите во вкладку **Bot**.
4. Прокрутите страницу вниз до блока **Privileged Gateway Intents**.
5. Активируйте переключатели напротив **Server Members Intent** и **Message Content Intent**.
6. Нажмите кнопку **Save Changes** внизу экрана.
7. Перезапустите контейнер с ботом:
   ```bash
   docker compose restart
   ```

> Если бот находится на 100 и более серверах, переключатель будет заблокирован до прохождения официальной верификации бота в Discord. Готовый текст заявки и подробное обоснование для команды Discord подготовлены в файле [`docs/discord-intent-request.md`](discord-intent-request.md).
