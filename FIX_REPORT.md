## Дополнительные исправления, найденные при совместной проверке

- Повторное ЧСП теперь транзакционно объединяет прежний снимок ролей с вновь снятыми ролями. Неоконченная амнистия не теряет данные при повторной блокировке.
- Верификация и verified-импорт не перезаписывают запись с незавершённым возвратом ролей.
- Ссылка на карточку апелляции записывается отдельным UPDATE без ненужного контрольного SELECT. При неопределённом результате записи уже доставленная карточка сохраняется; взаимодействие модератора может восстановить ссылку по точному ID.
- Защита ЧСА снимает staff-роли отдельными запросами, сохраняя только что выданную blacklist-роль.
- Свежая таблица апелляций сразу создаётся с `id`; ошибка миграции старой таблицы останавливает запуск вместо продолжения с несовместимой структурой.

## Правила и применение изменений

- Повторная апелляция после отказа доступна через **7 дней**, максимум **два обращения на каждый тип ЧС**. Один источник правила используется во всех обработчиках и БД.
- Вопросы pending-апелляций сохраняются без TTL. Ошибка архивирования оставляет исходный канал для повторной обработки. Если архивирование не настроено, закрытие канала остаётся доступным.
- При ошибке возврата ролей снимок сохраняется. После исправления разрешений можно повторить `/снятьчсп`; отсутствующему участнику возврат повторяется при входе.
- Для установки кода нужен `docker compose up -d --build`. Изменения только env применяются через `docker compose up -d --force-recreate`; изменения настроек в БД — через `docker compose restart`.
- Уже открытые формы и подтверждения старого формата нужно открыть заново из исходной карточки.

Проверки выполнены на Node.js `24.16.0` с подменой Discord API и модели БД; часть проверок использует установленный discord.js. Рабочие Discord и MySQL/MariaDB не использовались. Docker в окружении отсутствует, поэтому сборка образа и миграция на реальной БД здесь не выполнялись. Изменения подготовлены в рабочем дереве; публикация не производилась.
